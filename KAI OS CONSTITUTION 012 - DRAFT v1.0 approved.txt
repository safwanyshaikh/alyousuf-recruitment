# KAI OS CONSTITUTION 012

# TABLE CONSTITUTION

## Tables Are Operational Workspaces, Never Databases

**Status:** DRAFT v1.0

---

# PURPOSE

In every ATS and CRM,

tables become databases.

In KAI,

tables become operational workspaces.

A recruiter should comfortably spend an entire working day inside a table

calling,

filtering,

assigning,

updating,

submitting,

reviewing,

and completing work

without opening Excel.

---

# TABLE PHILOSOPHY

Tables do not store work.

Tables execute work.

Every row represents an operational responsibility.

Every column supports a decision.

Every interaction reduces recruiter effort.

---

# TABLE HIERARCHY

Every operational table follows one identical structure.

```text
Operational Summary

↓

Working Filters

↓

Bulk Action Bar

↓

Operational Table

↓

Quick Preview

↓

Intelligence Drawer

↓

Timeline
```

No module may violate this structure.

# ARTICLE T002

# ARTICLE T003

## Every Column Must Justify Its Existence

Columns exist only when they improve operational decisions.

Columns never exist because data is available.

Every column answers

"Will this help recruiters recruit faster?"

If not,

remove it.

# TABLE VALIDATION

Every future table must answer

1.

Can recruiters remain here for several continuous hours?

2.

Can daily work be completed without Excel?

3.

Can operations happen inline?

4.

Can repetitive work become bulk work?

5.

Does every visible column support a decision?

6.

Does this preserve organisational intelligence?

7.

Would experienced GCC recruiters naturally adopt this table?

If any answer is NO,

the table shall be redesigned.
